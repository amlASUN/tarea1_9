Preferencias



















¿Qué problema de seguridad descubres en el historial por haber enviado la inscripción con GET? ¿Qué método recomienda el artículo para un formulario como este y por qué?

Al enviar los datos mediante el método GET, toda la información confidencial introducida en el formulario (como contraseñas, correos y datos personales) queda expuesta y visible directamente en la URL almacenada en el historial del navegador, facilitando que cualquier persona con acceso al equipo pueda verla. El artículo recomienda utilizar el método POST para este tipo de formularios, ya que envía los datos de forma oculta en el cuerpo de la petición HTTP y no en la barra de direcciones.

¿Qué ocurre al enviar la inscripción con POST? Según el artículo, ¿qué tendría que haber en el servidor para procesar esos datos?

Al enviar la inscripción utilizando el método POST, los datos no se muestran en la barra de direcciones de la URL, pero si el servidor no está preparado, la página web suele devolver un error (como un error 405 Method Not Allowed). Según el artículo, para procesar dichos datos en el servidor se necesita un programa o script backend (como PHP, Node.js o Python) capaz de recibir, interpretar y gestionar la información enviada en el cuerpo de la solicitud.
